# T22 — seven-language evidence for general parser design

Checked-in report for 🎯T22. Numbers below are from `xbnf eval` on the
uninstrumented `Compiled.Parse` path (tree produced). JSON 64 KB
(`docs/parse-speed.md`, `make bench-stable`) is an auxiliary regression, not
evidence for these languages. Frozen Pigeon numbers are not rerun.

Manifests: `eval/testdata/{sql,xml,cpp,python,yaml,javascript,commonmark}/manifest.json`.
Standing commands: `make eval-corpus` (JSON smoke), `make eval-languages`.

## How to read a row

| Field | Meaning |
|---|---|
| Coverage | Declared subset. Exclusions are explicit; the file list is the denominator. |
| Correctness | Untimed `Parse` vs `expect`. Oracle disagreement is recorded, not hidden. |
| Oracle | Named reference. A missing binary is a **limit**, not a mock. |
| Cold compile | `syntax.Parse` + `engine.Compile`. |
| Cold first | First `Parse` after compile. |
| Warm varied | One `Parse` per fixture. |
| Warm identical | Repeated `Parse` of the first fixture (pool reuse). |
| Packed | Competing derivations. **GSS edges are not packed.** |
| DFA start | Start rule ran as a DFA, not GLL. |

Times are wall nanoseconds on this machine; they are not keep/discard claims.
Use `make bench-stable` for JSON 64 KB noise.

## Language results

Absolute times from one `xbnf eval` run on this host (Apple silicon). Re-run
the manifests rather than copying these nanoseconds into a speed argument.

### SQL — 🎯T22.2

| | |
|---|---|
| Grammar | `eval/testdata/sql/grammar.xbnf` |
| Coverage | Uppercase-keyword SELECT, FROM, WHERE, arithmetic, AND/OR, function calls with expr args. **Not** `COUNT(*)` (star-arg vs expr-list FIRST), joins, DDL, subqueries, windows. |
| Corpus | 2/2 in-repo fixtures (accept + `WHERE = 1` reject). |
| Oracle | PostgreSQL raw parser (`pg_query`). **Limit: not on PATH.** Fixtures classified independently. |
| Correctness | 2/2. |
| Notes | GLL. `#longest` on prefix operators (`>=` vs `>`). Keyword/IDENT still a FIRST overlap internally; `(?!KEYWORD)` is a DFA filter, not a FIRST-set proof. One-process grammar→compile→parse. |

### XML — 🎯T22.3

| | |
|---|---|
| Grammar | `eval/testdata/xml/grammar.xbnf` |
| Coverage | Well-formed elements with matching names via `%n`, attributes, text, comments. No DTD, PI, CDATA, entities, namespaces. |
| Corpus | 2/2. Unclosed `<root>` is the reject. |
| Oracle | libxml2 `xmllint --noout -` (well-formedness, not schema). Present. |
| Correctness | 2/2, oracle agreed. |
| Notes | Engine `%name` is intra-production capture from the named sibling span. Nested same-name tags work because each element instance has its own left position. FIRST of `%n` is any-char (not ε), or `>` after `</ %n >` is wrongly expected. |

### C++ — 🎯T22.4

| | |
|---|---|
| Grammar | `eval/testdata/cpp/grammar.xbnf` |
| Coverage | Preprocessed functions/globals, if/return, int/void/bool. **No** templates, classes, preprocessor, name lookup, or type-dependent syntax. |
| Corpus | 2/2 `.ii` (already preprocessed). `clang -E` cost is out of band. |
| Oracle | `clang -fsyntax-only -x c++ -`. This is **not** parse-only; Clang does semantic analysis. Present. |
| Correctness | 2/2, oracle agreed. |
| Notes | GLL. `#longest` on `==` vs `=`. Missing general facility: C++ templates and name lookup are not xbnf syntax success and are excluded, not faked with `|>`. |

### Python — 🎯T22.5

| | |
|---|---|
| Grammar | `eval/testdata/python/grammar.xbnf` |
| Coverage | `@col` line-indent: top-level column 0, one block indent `>0`. def/if/while, pass/return, calls. No async, decorators, or multi-level indent stacks. |
| Corpus | 2/2. Reject is a `def` header missing `:`. |
| Oracle | CPython `ast.parse` (AST, not bytecode). Present. |
| Correctness | 2/2, oracle agreed. |
| Notes | **Layout is an engine capability**, not a Python bypass: `@col` compares the indent of the current line (leading spaces/tabs) without wrap-skipping first. Wrap is `[ \t]` and comments, not newlines. Packed=1 on the accept fixture: GLL recorded a competing derivation on this tiny file. `@col(>parent)` as a captured indent is **not** implemented; `parent` currently means 0. |

### YAML — 🎯T22.6

| | |
|---|---|
| Grammar | `eval/testdata/yaml/grammar.xbnf` |
| Coverage | One-level `IDENT: value NEWLINE` mappings plus flow seq/map. No tags, aliases, nested indent stack, document markers. |
| Corpus | 2/2. |
| Oracle | PyYAML `safe_load` — **compose+construct**, not a syntax-only event dump. Present. |
| Correctness | 2/2, oracle agreed. |
| Notes | Start rule ran as a **DFA**. Parameterized indent (indent relative to a captured parent column) is the missing general facility; the subset avoids it rather than converting `|` to `|>`. |

### JavaScript — 🎯T22.7

| | |
|---|---|
| Grammar | `eval/testdata/javascript/grammar.xbnf` |
| Coverage | ECMAScript Script with **required semicolons**. function/let/const/if/return. **No** RegularExpressionLiteral, ASI, JSX, TS, modules. |
| Corpus | 2/2. Reject is a broken parameter list (not a missing semicolon: Acorn would accept ASI). |
| Oracle | Acorn (Script, not JSX/TS). Present on this host. |
| Correctness | 2/2, oracle agreed. |
| Notes | GLL. Lexical goal for `/` (RegExp vs division) is **not implemented**. Declared exclusion, not a silent corpus cut of regexp-heavy files — this standing fixture set never included them. |

### CommonMark — 🎯T22.8

| | |
|---|---|
| Grammar | `eval/testdata/commonmark/grammar.xbnf` |
| Coverage | ATX headings, paragraphs, fenced code, blank lines. No lists, links, emphasis, HTML blocks. Whole document must be consumed. |
| Corpus | 2/2. Reject is an unclosed fence. |
| Oracle | cmark structural parse/render. **Limit: not on PATH.** |
| Correctness | 2/2 xbnf. |
| Notes | Start rule ran as a **DFA**. Document interpretation (list indent, lazy continuation, setext vs paragraph) is the missing general facility. Empty ATX `#` is valid CommonMark; it is not used as a reject because that would be an xbnf-only failure against cmark. |

## Synthesis

Findings are tied to **measured mechanisms** on these fixtures, not to JSON 64 KB
or to unimplemented optimisations.

| Mechanism | Where it showed up |
|---|---|
| Unordered `\|` + `#longest` / `#assoc` | SQL/C++/JS operators; XML empty vs pair tags. Prefix operators cannot be ordered by source order. |
| Line-indent `@col` | Python layout. Wrap must not eat newlines; `@col` must not skip wrap before testing indent. |
| Intra-production `%n` capture | XML matching tags. FIRST of a ref cannot be ε. |
| DFA vs GLL split | YAML and CommonMark start-as-DFA on these subsets; SQL/XML/C++/Python/JS stay GLL. |
| Packed ≠ GSS | Python accept had Packed=1 with hundreds of GSS edges; XML accept Packed=0 with 60 edges. |
| Missing general facilities (explicit) | Nested indent stack (`@col(>parent)` as captured column); JS lexical `/` goal; C++ templates/name lookup; CommonMark list/lazy document interpretation; SQL `*` as an argument vs expr-list FIRST. |
| Oracle limits | `pg_query`, `cmark` absent here. xmllint, clang, CPython, PyYAML, Acorn present. |

**Do not conclude** that GLL is slow or fast relative to Clang or CPython from
these nanoseconds: the oracles do different work (Clang is not parse-only;
PyYAML constructs values; Acorn is a dedicated JS parser). Headline xbnf times
are only `Compiled.Parse` in-process.

**Do not conclude** from JSON 64 KB that these languages are linear or that
tree construction is free. JSON is one regular-ish data language. Python
already packed on a 65-byte file. SQL SELECT FIRST still needs disambiguators
on prefix operators.

Work sharing (GSS, pool reuse) is visible as warm-identical vs cold-first on
the same `Compiled`. That is the right place to look for pooling bugs (T21),
not a reason to share wrap memos across grammars.
