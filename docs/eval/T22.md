# T22 — seven-language evidence for general parser design

Checked-in report for 🎯T22. **Reopened 2026-09-06** (live set: SQL, XML,
**Go**, Python, YAML, JavaScript, CommonMark; C++ under `eval/testdata/cpp` is
historical). **This run:** every live language is `xbnf eval` **Failed=0**
against a **present** real-world parser oracle. Extending xbnf closed grammar
gaps (nestable `(?i:)` / `(?~i:)` match mode, XML prolog, UTF-8 gate). Pinned
fixture lists were not shrunk after misses.

Numbers are from `xbnf eval` on the uninstrumented `Compiled.Parse` path (tree
produced) against the **pinned third-party corpora** in
`eval/testdata/*/corpus/` (provenance: `eval/testdata/SOURCES.md`). JSON 64 KB
(`docs/parse-speed.md`, `make bench-stable`) is an auxiliary regression, not
evidence for these languages. Frozen Pigeon numbers are not rerun.

The file list in each live manifest is the denominator. Coverage text describes
what the grammar now claims; it is not a licence to drop pins.

Standing commands: `make eval-corpus` (JSON smoke), `make eval-languages`
(live seven, not C++).

## How to read a row

| Field | Meaning |
|---|---|
| Coverage | Declared xbnf subset. Files outside it still sit in the denominator. |
| Correctness | Untimed `Parse` vs independently assigned `expect`. |
| Oracle | Named reference. Absent binary → `oracle_limit`. |
| Cold compile | `syntax.Parse` + `engine.Compile`. |
| Cold first / warm varied / warm identical | `Compiled.Parse` phases; identical uses the pool. |
| Packed | Competing derivations. **GSS edges are not packed.** |
| DFA start | Start rule ran as a DFA. |

Times are one-host wall nanoseconds, not keep/discard claims.

## Synthesis

These are **measured** mechanisms on the pinned files, not JSON-64K conclusions.

| Mechanism | Evidence |
|---|---|
| Denominator honesty | Same pin lists as the miss run. SQL 4/4, XML 8/8, Go 5/5, Python 6/6, YAML 12/12, JS 5/5, CommonMark 2/2. No live file was removed. |
| Case-fold mode 🎯T24 | `(?i:term)` / `(?~i:term)` is a nestable match-time mode on any term. SQL keywords and Python `coding` cookies use it. `TestCaseFoldString`, `TestCaseFoldSequence`, `TestCaseFoldOffNested`. ASCII fold, not Unicode Simple Case Fold. |
| XML declaration / PI / DOCTYPE | Real well-formed files start with `<?` or `<!`; they now parse. `%n` tag match is exercised on success (pair_elem). |
| Layout `@col` | Python stdlib files now parse, so this run re-proves line-indent on real modules. |
| Capture `%n` | XML matching end-tags on the six well-formed documents. |
| Bytes vs Unicode | Python `badsyntax_pep3120.py` reject: `Compiled.Parse` refuses invalid UTF-8 (`TestInvalidUTF8Rejected`). |
| Event oracle ≠ construct | YAML uses `yaml.parse`. 2JQS is suite-valid and PyYAML-event-invalid; `expect` follows the named oracle; the file stays. |
| DFA vs GLL | All seven live start rules are GLL on this run (YAML is no longer start-as-DFA). Wrap DFA cannot host lookahead (Python hash comments stay in GLL). |
| Packed ≠ GSS | SQL `union.sql` Packed=198 with 97 181 GSS edges. XML success files Packed=0 with thousands of edges. |
| Missing facilities (explicit) | JS lexical `/` (not in this pin); YAML object construction; CommonMark inline structure beyond cmark agreement; Go CFG coverage omits generics/channels/select. |
| Oracle limits | None on this host. `pg_query`, `cmark`, xmllint, go/parser, CPython, PyYAML events, Acorn all present. |
| Live 100% gate | All seven live languages meet Failed=0 with a present syntax/tree oracle. |

**Do not** turn `go/parser` or CPython times into xbnf speed ratios: they do different work. **Do not** read JSON 64 KB linearity into SQL or Python. **Do not** treat CommonMark leftover consumption as a cmark-equivalent AST: these two files pass because cmark is present and xbnf consumed them.
