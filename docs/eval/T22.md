# T22 — seven-language evidence for general parser design

Checked-in report for 🎯T22. **Reopened 2026-09-06:** the live set is SQL, XML,
**Go**, Python, YAML, JavaScript, CommonMark. C++ under `eval/testdata/cpp` is
historical (`role: historical`) and is not a live language. Language-track
achievement requires a **present** real-world parser oracle and `xbnf eval`
**Failed=0** on that pinned manifest. Extending xbnf to close grammar gaps is
in scope. Dropping pinned fixtures after misses to mint 100% is not.

Numbers are from `xbnf eval` on the uninstrumented `Compiled.Parse` path (tree
produced) against the **pinned third-party corpora** in
`eval/testdata/*/corpus/` (provenance: `eval/testdata/SOURCES.md`). JSON 64 KB
(`docs/parse-speed.md`, `make bench-stable`) is an auxiliary regression, not
evidence for these languages. Frozen Pigeon numbers are not rerun.

The file list in each live manifest is the denominator. Rows below that are not
yet Failed=0 remain the honest current measurement; they do not retire the
reopened targets. Missing reference binaries are **limits**, not mocks, and
they block achievement.

Standing commands: `make eval-corpus` (JSON smoke), `make eval-languages`
(live seven, not C++).

## How to read a row

| Field | Meaning |
|---|---|
| Coverage | Declared xbnf subset. Files outside it still sit in the denominator. |
| Correctness | Untimed `Parse` vs independently assigned `expect`. |
| Oracle | Named reference. Absent binary → `oracle_limit`. |
| Cold compile | `syntax.Parse` + `engine.Compile`. |
| Cold first / warm varied / warm identical | `Compiled.Parse` phases; identical uses the pool. |
| Packed | Competing derivations. **GSS edges are not packed.** |
| DFA start | Start rule ran as a DFA. |

Times are one-host wall nanoseconds, not keep/discard claims.

## Synthesis

These are **measured** mechanisms on the pinned files, not JSON-64K conclusions.

| Mechanism | Evidence |
|---|---|
| Denominator honesty | SQL 0/4, XML 6/8 misses, YAML 9/12 not-ok, CommonMark 0/2 kept. Go 5/5. No live file was removed after the run. |
| XML declaration / PI / DOCTYPE | Every real well-formed XML file here starts with `<?` or `<!`; xbnf fails at byte 1. `%n` tag match is not the blocker on this corpus. |
| Layout `@col` | Still the Python facility; CPython stdlib files miss earlier (imports/docstrings), so this run does not re-prove indent. |
| Capture `%n` | Exercised on W3C not-wf rejects (both sides reject). Not exercised on success for this corpus because PI/DOCTYPE fail first. |
| Bytes vs Unicode | Python `badsyntax_pep3120.py` overaccept: engine treats `[]byte` as Go `string` without a UTF-8 gate. |
| Event oracle ≠ construct | YAML uses `yaml.parse`. 2JQS is suite-valid and PyYAML-event-invalid. |
| DFA vs GLL | YAML start-as-DFA; SQL/XML/Go/JS/Python/CommonMark GLL on this run. |
| Packed ≠ GSS | SQL `select_distinct.sql` Packed=1 with 135 GSS edges. JS misses have hundreds of edges and Packed=0. |
| Missing facilities (explicit) | Nested indent stack; JS lexical `/`; XML decl/DOCTYPE/PI; SQL case-fold keywords; CommonMark lists/links (unverified without cmark). Go CFG coverage omits generics/channels/select. |
| Oracle limits | `pg_query`, `cmark` absent — these **block** 🎯T22.2 / 🎯T22.8. xmllint, go/parser, CPython, PyYAML events, Acorn present. |
| Live 100% gate | Only Go currently meets Failed=0 with a present syntax oracle. Other live tracks remain open. |

**Do not** turn `go/parser` or CPython times into xbnf speed ratios: they do different work. **Do not** read JSON 64 KB linearity into SQL or Python. **Do not** treat CommonMark leftover consumption as a cmark-equivalent AST: with cmark absent, accept/`tree` files cannot pass.
