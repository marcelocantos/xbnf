# T22 — seven-language evidence for general parser design

Checked-in report for 🎯T22. Numbers are from `xbnf eval` on the uninstrumented
`Compiled.Parse` path (tree produced) against the **pinned third-party corpora**
in `eval/testdata/*/corpus/` (provenance: `eval/testdata/SOURCES.md`). JSON 64 KB
(`docs/parse-speed.md`, `make bench-stable`) is an auxiliary regression, not
evidence for these languages. Frozen Pigeon numbers are not rerun.

The file list in each manifest is the denominator. xbnf misses, overaccepts, and
oracle disagreements stay in the report. Subsets were not shrunk after seeing
results. Missing reference binaries are **limits**, not mocks.

Standing commands: `make eval-corpus` (JSON smoke), `make eval-languages`.

## How to read a row

| Field | Meaning |
|---|---|
| Coverage | Declared xbnf subset. Files outside it still sit in the denominator. |
| Correctness | Untimed `Parse` vs independently assigned `expect`. |
| Oracle | Named reference. Absent binary → `oracle_limit`. |
| Cold compile | `syntax.Parse` + `engine.Compile`. |
| Cold first / warm varied / warm identical | `Compiled.Parse` phases; identical uses the pool. |
| Packed | Competing derivations. **GSS edges are not packed.** |
| DFA start | Start rule ran as a DFA. |

Times are one-host wall nanoseconds, not keep/discard claims.

### SQL — 🎯T22.2

| | |
|---|---|
| Source | postgres/postgres `1f47e7b59b92` (REL_16_6), PostgreSQL licence. `src/test/regress/sql/{select,select_distinct,case,union}.sql`. |
| Coverage | Uppercase-keyword SELECT subset. Real regress scripts are lowercase, mixed statements, COPY, etc. |
| Oracle | PostgreSQL raw parser (`pg_query`). **Limit: not on PATH.** Expect comes from the regress suite (these files are valid inputs). |
| Result | **0/4 pass.** All four are `miss` (unconsumed input, or `case.sql` not starting with `SELECT`). Packed=1 on `select_distinct.sql`. GLL. |
| Note | A SELECT-only uppercase grammar does not parse PostgreSQL regress SQL. The miss is the evidence; the files were not dropped. |

### XML — 🎯T22.3

| | |
|---|---|

## Synthesis

These are **measured** mechanisms on the pinned files, not JSON-64K conclusions.

| Mechanism | Evidence |
|---|---|
| Denominator honesty | SQL 0/4, XML 6/8 misses, YAML 8/12 misses kept. No file was removed after the run. |
| XML declaration / PI / DOCTYPE | Every real well-formed XML file here starts with `<?` or `<!`; xbnf fails at byte 1. `%n` tag match is not the blocker on this corpus. |
| Layout `@col` | Still the Python facility; CPython stdlib files miss earlier (imports/docstrings), so this run does not re-prove indent. |
| Capture `%n` | Exercised on W3C not-wf rejects (both sides reject). Not exercised on success for this corpus because PI/DOCTYPE fail first. |
| Bytes vs Unicode | Python `badsyntax_pep3120.py` overaccept: engine treats `[]byte` as Go `string` without a UTF-8 gate. |
| Event oracle ≠ construct | YAML uses `yaml.parse`. 2JQS is suite-valid and PyYAML-event-invalid. |
| DFA vs GLL | YAML and CommonMark start-as-DFA; SQL/XML/JS/Python GLL. C++ start is GLL with empty work on some misses. |
| Packed ≠ GSS | SQL `select_distinct.sql` Packed=1 with 135 GSS edges. JS misses have hundreds of edges and Packed=0. |
| Missing facilities (explicit) | Nested indent stack; JS lexical `/`; C++ templates/`class`; XML decl/DOCTYPE/PI; SQL case-fold keywords; CommonMark lists/links (unverified without cmark). |
| Oracle limits | `pg_query`, `cmark` absent. xmllint, clang, CPython, PyYAML events, Acorn present. |

**Do not** turn Clang or CPython times into xbnf speed ratios: they do different work. **Do not** read JSON 64 KB linearity into SQL or Python. **Do not** treat CommonMark 2/2 consumption as a cmark-equivalent AST.

Work sharing (warm identical vs cold first) is visible on the same `Compiled`. T21 (wrap memo keyed by grammar) is why pooling is trustworthy enough to report warm-identical at all.
