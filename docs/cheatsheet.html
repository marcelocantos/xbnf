xbnf

Scannerless CFG notation. Regex-shaped fragments and recursive rules are the same language. There is no lexer. | is unordered. An unresolved ambiguity is a compile error.

Syntax: docs/xbnf.xbnf. Semantics: docs/plan.md. IR types are in package grammar.

New product, not a wbnf upgrade. wbnf is a PEG backtracker with ordered choice. xbnf does not keep that.

No matches. Clear search or switch slice.

What it is

IdeaConsequence
Scannerless String literals, classes, and rule refs all match against the input. No token stream.
Unordered | Source order has no meaning. A test that depends on alternative order is wrong.
GLL + layered DFA General CFG (including left recursion) is GLL. Regular rule bodies compile to character-class DFAs.
Self-host The engine must parse xbnf.xbnf.

File shape

stmt+
stmt  = COMMENT | rule | pragma
rule  = NAME mods* "->" term ";"

Comments: // line and /* block */. They are syntax, not IR.

Rules and modifiers

IDENT #lex -> /[A-Za-z_] [A-Za-z0-9_]*/ ;
ModifierRole
#lex Strictness lock: this rule must stay regular. Not the DFA switch — regularity is detected; #lex makes drift a compile error.

tok::label means: run tok, take the winning labelled alternative (longest match, priority on ties), succeed only if that winner is label. There is no lexer mode.

Pragmas

FormRoleIR
#wrap -> term ; Whitespace inserted between adjacent terminals. Scoped. Replaces wbnf .wrapRE. Wrap
#import "path" ; Include another grammar. Import
#macro name(args) { term } Expansion. later (arrai uses this). Macro

A nested { #wrap -> () ; … } turns wrap off inside that region — how character-level terminals are written. Default wrap in xbnf.xbnf:

#wrap -> (\s | COMMENT)* ;

Term layers

Tightest last. (term) groups and is not an IR node. () is empty.

L1 a > b > c stack Stack
L2 a | b | c or a |> b |> c (no mixing) Alt
L3 a b c sequence, trailing # directives Seq
L4 named atom with quantifiers Named Quant

Combinators

Sequence, alt, named

| is unordered. |> is committed choice (first match at this position). Mixing them in one alternation is an error; parenthesize to nest.

member -> STR ":" value ;
value  -> object | array | STR | "null" ;
alias=IDENT
op="+"

Delimited repetition

x separated by a delimiter. Leading/trailing commas in the grammar syntax allow a separator before the first / after the last item.

x:","         // x ("," x)*
x:,","        // optional leading ","
x:",",        // optional trailing ","
x:,",",       // both
member:","?     // JSON-style optional list, no trailing comma

IR: Delim with Leading / Trailing. A following ? is a separate Quant.

Directives

Trail a sequence: #name or #name=value.

@:op=("+" | "-")  #assoc=left

Vocabulary: #prefer / #avoid, #assoc=left|right|none, #priority, #longest. #longest is the default for regular-fragment rules. An unnecessary disambiguator is a warning. IR: Directive on Seq.

Stack

> is looser-to-tighter. @ is this stack (next tighter level, or the same level as infix/postfix). Left recursion is native.

expr -> @:op=("+" | "-")  #assoc=left
      > @:op=("*" | "/" | "%")  #assoc=left
      > op=("-" | "!") @
      > @ "(" expr:","? ")"
      | NUMBER
      | IDENT ;

@:op="+" is the idiom “infix + at this level”, operator captured as op.

Scope

{ decls term } on a stack level or as a rule body: nested rules/pragmas plus a body. Wrap-off inside /…/ is for a terminal that is several character-level terms.

NUMBER -> /{ #wrap -> () ;
    [0-9]+ ("." [0-9]+)? ;
}/ ;

IR: Scope.

Wrap, leaf, regularity

KnobOrthogonal job
#wrap What may appear between terminals (spaces, comments, nothing).
/term/ Whether a successful match is a tree or a string. Inner syntax is xbnf, not a second regex language.
Regular vs not A property of the rule body. Regular rules become DFAs. #lex only locks that property. 
NUMBER -> /{ #wrap -> () ;
    [0-9]+ ("." [0-9]+)? ;
}/ ;

Inside the braces, wrap is empty, so "." and digits concatenate with no injected space. Outside, #wrap -> \s* still applies around a NUMBER reference.

Ambiguity policy

A choice must be provably deterministic (bounded lookahead at compile time) or covered by an explicit # disambiguator. Otherwise: compile error. | is a set, not try-in-order.

Examples

First-slice complete grammar. From docs/examples/json.xbnf.

json   -> value ;
value  -> object | array | STR | NUMBER | "true" | "false" | "null" ;
object -> "{" member:","? "}" ;
member -> STR ":" value ;
array  -> "[" value:","? "]" ;

NUMBER -> /{ #wrap -> () ;
    "-"? ("0" | [1-9] [0-9]*) ("." [0-9]+)? ([eE] [+-]? [0-9]+)? ;
}/ ;

#wrap -> \s* ;

Precedence stack. From docs/examples/calc.xbnf.

expr -> "let" IDENT "=" @ ";" @
      > @:op="?" @:op=":"
      > @:op=("+" | "-")    #assoc=left
      > @:op=("*" | "/" | "%")  #assoc=left
      > op=("-" | "!" | "~") @
      > @ "(" expr:","? ")"
      | NUMBER
      | IDENT ;

Typical token: collapse xbnf, not a regex dialect. Wrap-off when several character-level terms sit next to each other.

IDENT -> /{ #wrap -> () ;
    [A-Za-z_] [A-Za-z0-9_]* ;
}/ ;

Designed, not first slice. From docs/examples/python-subset.xbnf.

file  -> (stmt @col(=0))* ;
block -> NEWLINE (stmt @col(>0)){1,} ;
